# 学习记录格式

学习记录位于 `./learning-records/`，并使用连续编号：`0001-slug.md`、`0002-slug.md` 等。按需创建目录，只有在写入第一条记录时才创建。

它们是教学中的 ADR：用于记录会引导未来会话的非显而易见的经验、关键洞察，以及用户声明的已有知识。它们用于计算最近发展区。

## 模板

```md
# {学到或确认内容的简短标题}

{1-3 句话：学到了什么，或确认了什么已有知识，以及它为什么会影响未来会话。}
```

这就是完整格式。一条学习记录可以只有一个段落。它的价值在于记录“这件事现在已经被知道了”以及“它为什么会改变下一步教学”，而不是填满一堆章节。

## 可选部分

只在它们真正增加价值时才包含。大多数记录不需要这些部分。

- **Status** frontmatter（头部元数据，`active | superseded by LR-NNNN`）：当早期理解后来被证明错误并被替换时很有用。
- **证据**：用户如何展示了这种理解，例如回答了问题、完成了练习、引用了已有经验。当这个判断之后可能被重新审视时很有用。
- **影响**：这为未来会话解锁或排除了什么。当它不显而易见时值得记录。

## 编号

扫描 `./learning-records/` 中现有的最高编号，并在此基础上加一。

## 什么时候写学习记录

满足以下任一条件时，写一条学习记录：

1. **用户展示了对某个非平凡内容的真正理解**：不只是接触过，而是有证据表明他们能正确使用这个概念。这会为下一步教学设置新的基础线。
2. **用户披露了已有知识**：“我已经知道 X。”记录下来，避免未来会话重复教学。同时记录用户声称的_深度_。
3. **一个误解被纠正了**：用户之前相信某个错误观点，现在理解了原因。这类记录价值很高，因为它们能预测相关主题中未来可能卡住的地方。
4. **使命因学习而发生变化**：用户发现自己真正关心的东西与原先想的不一样。交叉链接到 [[MISSION.md]] 并更新它。

### 什么_不_算

- 只是讲过的材料。覆盖不等于学习。等待证据。
- 已经在 [[GLOSSARY.md]] 中作为术语定义简洁记录的内容。不要重复。
- 逐会话活动日志。学习记录不是日记，而是决策级洞察。

## 取代

当后续记录与早期记录矛盾时，也就是用户理解加深或被纠正时，把旧记录标记为 `Status: superseded by LR-NNNN`，而不是删除它。理解如何演化的历史本身就是有用信号。
