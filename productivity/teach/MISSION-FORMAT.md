# MISSION.md 格式

`MISSION.md` 位于工作区根目录。它记录用户学习这个主题的_原因_。每一个教学决策，包括下一步教什么、展示哪些资源、设计哪些练习，都应该追溯到这个文档。

## 模板

```md
# 使命：{主题}

## 为什么
{1-3 句话。写出用户正在追求的具体真实世界目标。当他们拥有这项技能后，生活或工作会发生什么变化？避免使用“理解 X”这类抽象表述，要追问背后的结果。}

## 成功看起来像
- {用户将能够做到的一件具体、可观察的事情}
- {另一件具体事情}
- {…}

## 约束
- {时间、预算、既有承诺、学习偏好，或任何限制方法选择的因素}

## 不在范围内
- {用户明确表示现在不想追逐的相邻主题，用于保护最近发展区}
```

## 规则

- **每个工作区只保留一个使命。** 如果用户想学习两件不相关的事情，那就是两个工作区。
- **具体优先于抽象。** “十月前跑完半程马拉松”比“变得更健康”更好。“给团队交付一个 Rust CLI”比“学习 Rust”更好。
- **反推模糊表述。** 如果用户说不清为什么要学，先访谈他们，再写任何内容。糟糕的使命比没有使命更差。
- **现实变化时要修订。** 使命会变化。当用户目标移动时，更新这个文件，不要让过期使命继续引导未来会话。
- **保持简短。** 如果 `MISSION.md` 超过一屏，它就不再是指南针，而开始变成计划书。
