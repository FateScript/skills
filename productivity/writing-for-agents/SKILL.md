这是一份关于编写任何供代理使用的文档的参考：skill、`AGENTS.md` / `CLAUDE.md`，或通过指针访问的文档。它们的封装方式不同，写作方法却相同：同一组控制手段能让每份文档都变得可预测——让代理每次执行相同的_过程_，而不是产出相同的结果。

当你编写的文档是 skill 时，阅读 [`SKILL-MECHANICS.md`](SKILL-MECHANICS.md)，了解 frontmatter、调用方式选择和路由型 skills。

## 上下文指针

**上下文指针**是代理上下文中的一条引用：它指向上下文之外的某份材料，并编码何时应访问该材料的条件。skill 的 description 就是一种上下文指针；`AGENTS.md` 中指向某份文档的一行文字也是同一种对象。决定代理何时访问材料、以及访问有多可靠的，是指针的_措辞_，而不是它指向的目标。必要材料如果藏在措辞薄弱的指针后面，就会造成行为波动缺陷：先强化措辞，只有强化仍无效时才将材料内联。

指针承担两项工作——说明材料是什么，并列出应触发访问的**分支**（分支是文档所处理的一种独立情形，因此不同运行会沿不同路径穿过文档）。始终加载的指针中，每个词都会在每轮对话消耗成本，因此应比正文接受更严格的删减：

- **将引导词放在最前面**——指针正是在这里发挥触发作用。
- **每个分支只设一个触发条件。** 仅仅给同一分支换名的同义词，只是把一个分支写了两遍；合并它们，只保留真正不同的分支。
- **删除正文已经承载的身份说明。**

## 两类负载

你添加的每份文档和每个指针，都会消耗以下两种预算之一：

- **上下文负载**——始终加载的材料占用代理上下文窗口的成本：`AGENTS.md` 中的一行、skill description，以及每轮对话中无论是否触发都会留在上下文并消耗 token 与注意力的所有内容。
- **认知负载**——人需要承担的成本：有哪些文档，以及何时应访问每份文档。人就是索引。它并非需要最小化的成本——而是人类自主权的代价；把它花在人类判断真正重要之处，在不需要人类判断之处将其移除。

只有通过指针才能访问的材料，以指针自身那一行的代价避开了上下文负载；完全没有指针的材料则完全依靠认知负载。

## 信息层级

文档由两类内容构成——**步骤**（代理按顺序执行的动作）和**参考信息**（按需查阅的定义、规则与事实）——两者可以自由组合：全是步骤（操作流程）、全是参考信息（评审规则、本 skill），或两者兼有。核心决策是把每项内容放在**信息层级**的哪一层；这是一架按代理对材料的即时需要程度排列的梯子：

1. **文件内步骤**——主要层级：代理要按顺序做什么。
2. **文件内参考信息**——按需查阅。它们往往确实是一组扁平、平级的内容（例如评审的每条规则都位于同一层）——这种安排完全合理，并非坏味道。
3. **披露式参考信息**——移到单独文件中，借助上下文指针访问，只在指针触发时加载。其范围可以从同一文件夹中的相邻文件，一直延伸到存放于任意位置、可由任何文档指向的完全外部参考资料。

下移得太少，顶层就会臃肿；下移得太多，又会隐藏代理真正需要的材料。如何处理这组张力就是全部决策所在。

**渐进式披露**是沿梯子向下移动——把内容移出主文件并放到指针之后——从而让顶层保持清晰易读。它首先不是一种 token 优化，而是保护层级结构的方法。分支是最干净的披露测试：内联每条分支都需要的内容，只把部分分支才会访问的内容放到指针之后。对于包含步骤的文档，本应披露却仍留在文件内的参考信息会掩埋步骤，使代理是否注意到它们变成一次抛硬币——这影响的是行为波动，而不只是可读性。

**共置**是文件内部的配套原则：层级决定一项内容要下移_多远_，共置则决定内容到达某处后_与什么相邻_。将同一概念的定义、规则和注意事项放在同一标题下，而不是四处分散；这样阅读其中一部分时，也会把相邻内容带入注意力。判断标准是：文档读起来应像专门为代理编写的文档——相关材料归组后便有这种感觉，四散时则没有。（这不同于重复：重复是在两处表达同一含义；散布则是把一个含义拆散到多处。）

**蔓延**是这里的失败模式：文档单纯过长，即使每一行都仍然有效且独一无二。过量内容会稀释注意力，每增加一行，也就多了一行需要持续保持相关。解决办法仍是这架梯子：把参考信息放到指针后披露，并按分支或顺序拆分，让每条路径只携带它真正需要的内容。

## 步骤与完成标准

每个步骤都以一项**完成标准**结束——即告诉代理工作何时完成的条件。两种属性使它成为有效控制手段：

- **清晰度**——代理能否分辨已完成与未完成？模糊的边界（“已经理解”）会诱发**过早完成**：步骤尚未真正完成便结束它，注意力滑向_赶紧完成_。眼前仍然可见的后续步骤——**完成后步骤**——产生向前拉扯；标准的清晰度则提供阻力。按此顺序防御：**先收紧边界**（局部且成本低）；只有当边界本质上无法清晰，_并且_你确实观察到抢跑时，才通过拆分流程隐藏后续步骤——而隐藏只有跨越真正的上下文边界（交接或派遣子代理）才有效；内联调用会让后续步骤继续留在上下文中，什么也没有清除。
- **要求强度**——标准要求做到什么程度。“每个修改过的模型都已涵盖”会迫使代理进行全面工作，而“生成变更列表”不会。要求强度推动**实地工作**——代理在任务内部完成的挖掘，它隐含在措辞中，而不是另写成一个步骤——且不受步骤边界限制：“应用每条规则”能够约束一组扁平的参考信息，就像“完成每个步骤”能够约束一段流程一样；因此，即使一份文档全部由参考信息构成，也仍能设定穷尽性门槛。

最强的标准既可检查，又要求穷尽。

## 何时拆分

把一份文档拆成两份，会消耗两类负载中的一种，因此只有拆分确有收益时才这样做：

- **按顺序拆分**——当完成后步骤会诱使代理草率处理眼前步骤时，拆分一段连续步骤。让后续步骤保持不可见，能促使代理在当前任务中做更多实地工作。也要警惕反向影响：合并流程会让每个步骤看见随后的一切，从而诱发过早完成。
- **按调用方式拆分**——这是 skill 特有的情况：参阅 [`SKILL-MECHANICS.md`](SKILL-MECHANICS.md)。

## 引导词

**引导词**是一个已存在于模型预训练中的紧凑概念，代理在执行文档时会用它思考（例如 _lesson_、_fog of war_、_tracer bullets_）。将它作为 token 反复使用，而不要把整句话反复写出；它会逐渐形成分布式定义，并借用模型已有的先验，以最少 token 锚定整片行为。自造词也能发挥作用，前提是定义清楚，但新造词无法借用任何先验——预训练词免费提供的内容，你必须用定义 token 来支付；因此先寻找已有词。

它会锚定两次。在正文中锚定_执行_：每当这个词出现，代理都会调用同一种行为；在扁平参考信息中，它还会把注意力集中到需要寻找的一类事物上。在指针中锚定_调用_：当同一个词同时存在于提示词、文档和代码库中时，代理会把这种共享语言与材料关联起来，从而更可靠地访问材料。

主动寻找使用引导词重构的机会。在三个地方分别拼写出的三联概念、用整句话含糊指向一个想法的指针——这类段落都急需压缩成单个 token：

- “快速、确定、低开销” → _tight_（一个 _tight_ 循环）。
- “一个你相信的循环” → _red_——模糊的门槛变成二元、可观察状态（循环会因 bug 变成 _red_，或者不会）。

你会获得双重收益：更少的 token，以及一个更鲜明、可供代理挂载思维的钩子。假设每份文档都存在可由引导词淘汰的重复表述——去找出它们。

**否定式指令**是紧邻这一控制手段的失败模式：通过禁止某种行为来引导，会把被禁止的行为带入上下文，反而使其更容易发生。_不要想大象_，结果满脑子只剩大象；否定词只是一个弱修饰语，压不过被强烈激活的概念，于是禁令读起来一半像是在要求做那件事。提示**正向目标**——直接说明目标行为（“写单行注释”），让被禁止的行为根本不出现。只有当某项硬性护栏无法用正向方式表述时，禁止语句才值得保留；即便如此，也要把它与正向目标配对，让注意力落在该做什么上。

## 删减

- 让每个含义都只有一个**单一事实来源**：一个权威位置，使行为变更只需编辑一处。**重复**——同一含义出现在多个位置——会增加维护和 token 成本，并把某个含义在层级中的显著程度抬高到超过其真实级别。（这恰好是引导词的意外反面：引导词有意重复 token，却从不重复含义。）
- **环境**本身也是事实来源——`package.json` 脚本、配置文件、目录布局、`--help` 输出——而重复描述这些内容的文档就是一份**缓存**：它复制了查询结果，只有在查询昂贵时，其负载才有价值。只缓存代理无法通过查看环境发现的内容：未成文的约定、某项选择背后的原因、任何配置都不会透露的陷阱。将单文件、单命令即可完成的查询留给环境，因为环境中的信息不会过时。
- 检查每一行的**相关性**：它是否仍与文档的职责有关？一行内容可能因为从未影响任务（纯粹说明，或本应披露出去的分支），或因其描述的行为与世界发生变化而失去相关性。较短的文档更容易保持相关。若没有删减纪律，默认结局就是**沉积**：过时内容层层堆积，因为添加让人安心、删除令人不安，直到你必须像取芯一样向下钻，才能找到仍然有效的内容。
- 逐句寻找**无效指令**：模型本来就会默认遵循的指令，花费了负载却没有产生任何作用。判断标准——相较默认行为，它是否改变了行为？——取决于模型，而非读者：两个人对一条指令是否无效存在分歧，本质是在争论默认行为；应通过实际运行文档解决，而不是辩论。如果一个句子未通过测试，就删掉整个句子，不要只修剪几个词。这个测试同样适用于引导词：弱到无法超越默认行为的词（代理本来就算比较仔细时还说 _be thorough_）也是无效指令；修复方式是换成更强的词（_relentless_），而不是换一种技术。
